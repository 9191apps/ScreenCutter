# 纵向滚动长图

日期：2026-10-23。这一阶段不放进区域截屏的 `CapturePhase`。框选仍然用现有遮罩，真正滚动和拼接由 `Scroll/` 单独完成。

## 用户看到什么

菜单「滚动长图」后，在光标开始拖动的那一块屏幕上框出**当前可见的滚动区域**。松开后操作条只有「开始滚动」和「取消」。不在这里做标注。

开始之后遮罩藏起，桌面会短暂露出来，下面的窗口自己滚动。拼完把 PNG 和 TIFF 写入剪贴板，并显示「已复制」。

两种停法：

- 滚到内容不再变化，视为到底，只提示已复制。
- 对不齐、一步都没滚动、或达到步数上限：剪贴板里留下已经拼上的图，并说明原因（未能滚动、未能对齐、没有滚到底等）。

只做纵向。不做横向，不做元素隐藏，不把滚动过程插进标注。

## 坐标和取图

框选结果仍是 `ScreenSelection`：AppKit 全局矩形，限制在拖动开始的那块屏幕里。每一帧调用现有的 `ScreenCaptureService.capture`，所以像素对齐和「先藏遮罩再截」跟区域截屏一致。

滚动事件用 `CGEvent` 的像素滚轮。macOS 把滚轮交给**当前鼠标指针下方**的窗口，而不是只看 `CGEvent.location`，所以每步先把指针移到选区中心（Quartz 全局坐标，由 AppKit 底边原点换算），再发 `mouseMoved` 和滚轮。滚轮 `wheel1` 为负，让内容向上走、露出下面的部分。每步大约滚选区像素高度的 35%。捕获结束后把指针移回开始前的位置。

若选区下的窗口不滚动，第一帧和下一帧相同，按下面的失败条件停，并提示未能滚动，不把它当成「已经到底」。

## 自动模式：测位移，再裁条

自动模式**不再**用「在全高度里搜重叠、取得分最低的一段」做主对齐。那种做法在代码编辑器等重复行背景上容易咬住短假重叠，长图会出现行号跳跃、中间缺段。

当前流程（`ScrollCapture` + `ScrollShift`）：

1. 滚一步后先等画面停稳：连续两次截屏几乎一样再取样，避免惯性或重绘中途对齐。
2. 在**上一帧**与**本帧**之间，只在「本步预期新行数 ± 容差」的窄范围内，测量内容向上移动了多少行（`newRows`）。对齐时比较的是整段重叠带：`previous[newRows…]` 与 `next[0…]`，而不是在多个重叠高度里挑一个最低 MAD。
3. 测得的 `newRows` 合法且平均差低于阈值时，把 `next` 底部 `newRows` 行接到长图下面；测不到则保留已拼部分并提示「画面未能对齐」。
4. 滚轮步长只用来划定搜索容差，**不**假定目标 App 一定滚了同样多的像素（行对齐的编辑器会有偏差，容差内用实测位移为准）。

像素比较仍走 `ScrollStitch` 的行差函数（左侧行号区采样更密），但仅服务于位移测量，不再作为「主拼图策略」。

## 手动模式：重叠拼接

手动模式仍用 `ScrollStitch.join`：用户自己滚，步长不固定，停稳后在「已拼图底部」与「新帧顶部」之间搜重叠。对不上时提示往回滚，不强行裁条。

菜单里「手动滚动长图」和「滚动长图」并列。框选仍然用同一套遮罩，操作条只把按钮换成「开始手动滚动」。开始后遮罩隐藏，选区外侧浮出控制条：状态、完成、取消。

控制条是 `.nonactivatingPanel`：不抢焦点，选区下的窗口还能继续接收滚轮。控制条按 PID 排除，不会出现在长图里。

程序每 150 ms 采一帧；停稳后才 `join`。点「完成」后最多再等 3 秒补最后一段。若全程没有拼接出新段落，会说明只保留了第一屏。

已知限制：两种模式都不隐藏元素。固定表头、工具栏或悬浮横幅每帧在同一位置，会让对齐变难或在长图里重复出现。把选区收紧到纯滚动内容区域更稳。

## 何时停（自动）

最多 20 步。

- 还没有接上任何新行，下一帧就和上一帧几乎一样：失败，说明未能滚动。
- 已经接上过，下一帧几乎不变：成功，视为到底。
- 测不到合法位移：失败，说明未能对齐。
- 走满 20 步仍不能确认到底：失败，说明没有滚到底。

## 代码

- `Scroll/ScrollStitch.swift`：缓冲、行差、手动 `join`。
- `Scroll/ScrollShift.swift`：自动模式的位移测量与裁条追加。
- `Scroll/ScrollCapture.swift`：自动滚轮、停稳取样、位移拼接。
- `Scroll/ManualScrollCapture.swift`：手动采样与 `join`。
- `Overlay/ManualScrollPanel.swift`：手动控制条。

## 为何不用 Accessibility 自动滚

部分 App 可通过 AX 按行滚，但需要额外权限、实现因应用而异，且并非所有可滚区域都可 AX 定位。当前产品以 CGEvent + 实测位移为主；AX 可作为后续增强，不在本路径里混用两套滚动物理。
