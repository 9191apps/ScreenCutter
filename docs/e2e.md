# 真实环境 E2E 检查

这份文档覆盖**需要真实桌面、真实截屏和真实鼠标键盘**的验证。它不参与 `xcodebuild test`，也不进 CI：

- 需要辅助功能和屏幕录制权限；
- 会移动真实鼠标、打开全屏遮罩，可能抢焦点；
- 依赖当前显示器尺寸和运行中的 App。

日常回归继续用单元/视图测试：

```sh
xcodebuild -project ScreenCutter.xcodeproj -scheme ScreenCutter \
  -destination 'platform=macOS,arch=arm64' test
```

真实环境检查放在发布前，或者改动覆盖层、截屏、保存流程之后跑一遍。

## 前置条件

1. 用 Xcode 运行 scheme **ScreenCutter**，保持 App 在运行。
2. 给终端（或你用来跑脚本的 App）打开：
   - 系统设置 → 隐私与安全性 → **辅助功能**
   - 系统设置 → 隐私与安全性 → **屏幕录制**
3. 确认只有一份 ScreenCutter 在跑；多实例时用 `E2E_APP_PID` 指定要驱动的那一个。
4. **解锁屏幕并保持登录会话**。锁屏或屏保会挡住合成事件和全屏遮罩。
5. 默认使用单显示器、区域截屏快捷键 ⇧⌘2。如果改过快捷键，用环境变量覆盖，或改走菜单入口。

检查权限和屏幕信息：

```sh
scripts/e2e/build.sh
scripts/e2e/bin/e2e-tools check-permissions
scripts/e2e/bin/e2e-tools screens
```

如果构建时报 SDK/编译器不匹配（多见于同时装了 beta Xcode），指定一个稳定的开发者目录：

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer scripts/e2e/build.sh
```

## 自动冒烟

```sh
E2E=1 scripts/e2e/smoke.sh
```

它做这些事：

1. 检查辅助功能/屏幕录制权限，找到运行中的 ScreenCutter；
2. 发 ⇧⌘2，等待覆盖层窗口出现；
3. 拖出一块选区，等待操作条；
4. 点「标注」，等待标注工具条；
5. 等冻结图就绪后画一个矩形；
6. 按 ⌘Z 撤销；
7. 按 Esc 退出，并确认覆盖层窗口消失；
8. 把关键界面截图写到 `scripts/e2e/artifacts/`。

它**验证的是流程和状态转换**，不会对截图做像素断言。截图需要人眼确认：工具条默认高亮、矩形确实画出来、撤销后消失、没有残留遮罩。

可用环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `E2E_APP_PID` | 自动查找 | 指定 ScreenCutter 进程 |
| `E2E_HOTKEY_KEYCODE` | `19` | 数字 `2` 的虚拟键码 |
| `E2E_HOTKEY_FLAGS` | `cmd+shift` | 快捷键修饰键 |

失败时脚本会尽量按 Esc 关闭覆盖层；`bin/` 和 `artifacts/` 都已加入 `.gitignore`。

## 工具速查

所有命令都在 `scripts/e2e/bin/e2e-tools`：

```sh
e2e-tools key 19 cmd+shift          # 发快捷键
e2e-tools drag 300 300 900 700      # 真实鼠标拖拽
e2e-tools click 705 930             # 点击
e2e-tools type "测试文字"            # 输入 Unicode 文本
e2e-tools ax-dump <pid>             # 打印辅助功能树
e2e-tools ax-press <pid> 标注        # 按标题点按钮
e2e-tools ax-press <pid> "" --desc green   # 颜色按钮按描述点
e2e-tools windows <pid>             # 查窗口 ID / 层级 / bounds
e2e-tools overlay-window <pid> 5    # 等覆盖层窗口，打印窗口 ID
e2e-tools screenshot out.png <id>   # 按窗口截图（全屏截图抓不到 shielding 窗口）
e2e-tools frontmost <pid>           # 断言 App 在前台
e2e-tools pb-dump /tmp/pb-backup    # 备份剪贴板
e2e-tools pb-restore /tmp/pb-backup # 恢复剪贴板
e2e-tools pb-save-image /tmp/x.png  # 把剪贴板里的 PNG 存盘
```

## 手工清单

自动冒烟只走一条主路径，下面这些仍然建议在发布前手动过一遍。

### 区域截屏与选区

- [ ] ⇧⌘2 打开覆盖层，整个屏幕变暗，光标为十字
- [ ] 拖出选区；Shift 约束正方形，空格+拖拽平移
- [ ] 松开后出现操作条，选区边框上有 8 个手柄
- [ ] 拖角/拖边改尺寸；拖选区内部整体移动；方向键 1pt、Shift+方向键 10pt
- [ ] 选区贴近屏幕四边时，操作条不越界、不挡手柄
- [ ] 点击压暗区域或 Esc 取消，覆盖层完全消失

### 标注

- [ ] 点「标注」后出现冻结图，选区工具条消失，标注工具条出现
- [ ] 默认「矩形」「中」和红色有明确选中态；颜色圆点显示真实颜色
- [ ] 矩形、箭头、画笔、文字都能画；文字回车提交
- [ ] 画完的标注自动选中：矩形显示手柄，箭头/画笔/文字显示虚线框
- [ ] 拖动选中的标注可以移动；矩形仍可拖手柄缩放
- [ ] Delete/Backspace 或工具条「删除」可以删除选中标注
- [ ] 撤销可以恢复移动、缩放和删除；删除后撤销会重新选中该标注
- [ ] 选中标注后方向键微调 1pt，Shift+方向键 10pt
- [ ] 文字工具下点击是新建文字；移动/删除文字前先切到矩形、箭头或画笔工具选中它
- [ ] 箭头尖端是尖的，线杆不盖过箭尖
- [ ] 矩形画完自动选中，显示 8 个手柄；拖手柄缩放
- [ ] 切换到箭头/画笔后，点击矩形仍能选中并缩放；拖拽才画新图形
- [ ] 调整大小后 ⌘Z 回到调整前的尺寸，再 ⌘Z 才删除矩形
- [ ] 撤销按钮和 ⌘Z 行为一致
- [ ] 点空白处取消选中并开始画新图形
- [ ] 工具条不遮挡选区内容，右侧没有多余空白

### 复制与保存

- [ ] 复制后剪贴板里是 PNG/TIFF，尺寸等于选区像素尺寸，标注已烘焙
- [ ] 复制后覆盖层关闭，出现「已复制」提示
- [ ] 保存面板默认桌面，文件名形如 `ScreenCutter 2026-10-24 11.51.43.png`
- [ ] 保存出的图片包含标注，尺寸正确
- [ ] 取消保存后回到标注界面，App 仍在前台，工具条是激活态
- [ ] 从操作条（未标注）取消保存后，选区和操作条还在

### 整屏与窗口

- [ ] ⌥⇧3 整屏截屏，标签是显示器像素尺寸，操作条在屏幕内
- [ ] ⌥⇧4 窗口截屏，悬停高亮和标题正确，点击后出现操作条
- [ ] 窗口截屏的选区不跨屏

### 环境相关

- [ ] 多显示器：每块屏幕的遮罩、跨屏拖选限制、操作条位置
- [ ] 滚动长图：框定可滚动区域，滚动后可拼接；中途失败有提示
- [ ] 快捷键冲突提示和「更改快捷键」流程
- [ ] 菜单栏图标入口和菜单项（不只用快捷键）

## 已知坑

- **锁屏/屏保**：`check-permissions` 会检查前台是不是 `loginwindow`，锁屏时直接拒绝运行。解锁后再跑。
- **全屏截图看不到覆盖层**：覆盖层在 `CGShieldingWindowLevel`，`screencapture -x` 会把它排除。用 `overlay-window` 拿窗口 ID，再 `screenshot <path> <id>`。按窗口截图里选区是白色，因为桌面没有参与合成，不是 bug。
- **合成事件粘住 Shift**：发完 ⇧⌘2 后，鼠标事件可能继承修饰键。工具里每个鼠标事件都显式清空 `flags`，所以拖拽不会被约束成正方形。
- **AXPress 在模态切换时返回 `-25204`**：面板可能已经打开，动作结果和错误码不一致。脚本应在动作后重新检查界面状态，不要只看返回值。
- **保存面板的路径输入**：用合成 ⌘⇧G 在保存面板里输入路径不稳定；自动验证建议用默认桌面目录，结束后删除测试文件。手工检查时正常输入即可。
- **辅助功能权限按终端 App 记**：换了终端或 IDE 内置终端，可能需要重新授权。

## 清理

- 用 `pb-dump` / `pb-restore` 备份和恢复剪贴板，避免覆盖用户内容。
- 删除保存测试产生的 PNG；不要动用户已有的同名文件。
- 失败时确认没有残留覆盖层窗口：`overlay-window <pid> 0` 应返回非 0。
- `scripts/e2e/bin/`、`scripts/e2e/artifacts/` 都是生成物，不会提交。
